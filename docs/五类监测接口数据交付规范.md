# 五类监测接口数据交付规范

版本：0.1.0，需求草案，待协同课题组确认。

## 1. 交付边界

电磁、声波、无线SDR、网络IDS和业务量测五类数据由对应协同课题组提供。本方提出数据需求，负责接入校验、设备／时间关联及识别、防御调用；提供方负责采集或生成方法、原始证据和字段解释。具体团队、设备及交付周期由双方确认，本文不代表提供方已经具备全部能力。

统一交付为“JSON观测事件＋独立证据文件”。事件由公共字段、metadata（采集元数据）和data（领域观测／结果）组成。五类接口使用同一事件头，按source_type区分数据结构。

- [机器可校验的JSON Schema](interfaces/monitoring-event.schema.json)，采用[JSON Schema 2020-12](https://json-schema.org/draft/2020-12)。
- [五类事件及缺失事件示例](interfaces/monitoring-events.examples.jsonl)。示例仅演示结构，example-only路径不对应实际文件，数值不作为实测数据或效果证明。
- [资料依据与真实获取条件](架构图依据说明.md#2-数据可获取性)。资料用于说明数据有何获取途径，不代替提供方的能力确认。

## 2. 公共事件结构

除注明可选的字段外，下列字段均须出现。允许为空的字段使用null；枚举中的unknown用于明确未知，不能自行填入推测的确定值。

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| schema_version | string | 固定为0.1.0。 |
| event_id | string | 提供方生成的事件唯一标识；与provider_id共同标识事件，重传保留原标识。 |
| provider_id、source_id | string | 数据提供方及实际采集／生成节点标识，由双方建立清单。 |
| source_type | enum | em、acoustic、wireless、ids、business。 |
| scenario_id | string或null | 双方约定的场景／试验标识，无法映射时为空；不编码攻击类别。 |
| timestamp | string | 本条事件生成时间，带时区的ISO 8601时间。 |
| observed_at | string或null | 本次观测窗口起始时间；有证据时必填，不能用事件发送时间替代。 |
| time_source | string或null | 观测时钟来源；未知时为空。 |
| time_quality | enum | synced、unsynced、unknown；是来源报告的同步状态，不保证时钟未受攻击。 |
| related_asset_ids | string[] | 已知关联的底座设备列表；未知时为空数组。 |
| association_basis | enum | configured（配置映射）、inferred（估计关联）、unknown。不得从攻击真值填入目标。 |
| status | enum | normal、anomaly、offline、unknown；表示提供方的初步观测判断，未判断时为unknown。 |
| confidence | number或null | 初步判断置信度，范围[0,1]；未计算时为空。 |
| data_origin | enum | measured、replay、synthetic；说明提供方交付数据的来源。 |
| data_quality | enum | valid、degraded、missing；描述采集／交付质量，不表示有无攻击。未校准不必然等于数据损坏。 |
| missing_reason | string或null | 整次观测缺失或退化的原因；missing时必须填写。 |
| raw_data_uri | string或null | 主证据文件的包内相对路径或双方约定地址；有数据时必须可读取。 |
| raw_data_format | enum或null | sigmf、wav、eve_json、pcap、pcapng、csv；与接口类型匹配。 |
| raw_metadata_uri | string或null | SigMF元数据文件地址，交付SigMF时必填；其他格式可空。 |
| metadata | object | 下文对应接口的采集配置与证据窗口。 |
| data | object | 下文对应接口的领域观测／结果；可选结果无需强行提供。 |
| field_status | object，可选 | 以字段路径为键说明显式空值或条件不满足，例如data.claimed_transmitter_id: not_decoded。 |
| extensions | object，可选 | 协商后的扩展字段；不得放入真实攻击标签、真实攻击者或隐藏受害状态。 |

metadata.start_time和end_time使用带时区的ISO 8601时间，描述证据覆盖窗口，end_time不早于start_time；单点事件允许相同。设备自身时间另存device_timestamp，不用真值对观测时间进行“纠正”。频率、采样率均使用Hz，时长使用ms，计数为非负整数。

## 3. 各接口的metadata与data

以下metadata为正常或退化交付的必填项；条件字段允许空值并说明原因。表中的data除明确要求外均为可选，由提供方确认支持范围；本方需要时也可在识别侧计算，但应单独标明算法来源。

### 3.1 电磁接口（em）

原始证据要求：SigMF波形，优先提供复数I/Q；若提供方仅能交付实数时域信号，需注明并确认下游兼容性。[依据R8/R9/R14](架构图依据说明.md#3-支撑材料)

| 位置／字段 | 类型／单位 | 交付要求 |
| --- | --- | --- |
| metadata.start_time、end_time | string | 证据窗口。 |
| metadata.sample_rate_hz、sample_count、channel_count | number Hz、integer、integer | 正数；sample_count为每通道样本数，复数I/Q的一对计为一个样本。 |
| metadata.sample_format | string | SigMF样本类型，如cf32_le或rf32_le，须与文件一致。 |
| metadata.capture_frequency_hz | number Hz或null | 接收机调谐中心；直接采样可空，此时以通带／前端说明补充覆盖范围。 |
| metadata.capture_bandwidth_hz | number Hz | 本次实际采集通带宽度，不能填写整个仪器调谐范围。 |
| metadata.gain_db、unit、calibration_state | number dB或null、string、enum | 实际增益；幅度单位；calibrated、uncalibrated或unknown。 |
| data.center_frequency_hz、bandwidth_hz、duration_ms、snr_db | number或null | 信号特征估计；中心频率与接收机调谐中心分开记录。 |
| data.power_dbm、noise_floor_dbm | number dBm或null | 仅在有效校准后提供，不将接收功率当成攻击源发射功率。 |
| data.signal_pattern、doa_deg、location | string、number、object，均可空 | 信号类别及定位结果，需相应算法／设备支持。 |

### 3.2 声波接口（acoustic）

原始证据要求：WAV的PCM片段，允许单通道；多通道须说明排列与同步方式。[依据R10](架构图依据说明.md#3-支撑材料)

| 位置／字段 | 类型／单位 | 交付要求 |
| --- | --- | --- |
| metadata.start_time、end_time | string | 证据窗口。 |
| metadata.sample_rate_hz、sample_count、channel_count | number Hz、integer、integer | 正数，定义同电磁接口。 |
| metadata.bit_depth | integer | 8、16、24或32；与WAV头一致。 |
| metadata.gain_db、input_range | number或null | 增益dB、采集输入量程V；量程定义与换算系数由提供方说明。 |
| metadata.unit、calibration_state | string、enum | 如adc_count、normalized、Pa；校准状态同电磁接口。 |
| data.dominant_frequency_hz、bandwidth_hz、duration_ms、snr_db | number或null | 主频、带宽、持续时间、信噪比。 |
| data.sound_pressure_db、background_noise_db | number或null | 校准后的dB SPL，空气参考声压20 μPa；未校准不得填写绝对声压。 |
| data.signal_pattern、doa_deg、location | string、number、object，均可空 | 信号类别和定位估计；单通道不默认支持定位。 |

### 3.3 无线SDR接口（wireless）

原始证据要求：复数I/Q及SigMF元数据，不能以指纹编号代替I/Q。metadata复用电磁结构，但sample_format必须是复数类型，capture_frequency_hz须明确。[依据R8/R9](架构图依据说明.md#3-支撑材料)

| data字段 | 类型／单位 | 交付条件 |
| --- | --- | --- |
| center_frequency_hz、bandwidth_hz、rssi_dbm、snr_db | number或null | 频率／带宽估计及接收质量；rssi_dbm需有效功率校准。 |
| claimed_transmitter_id、frame_type | string或null | 仅在能够解码时提供；是报文声明身份，不是真实设备身份。 |
| receiver_id、channel_id | string或null | 关联的业务接收端和信道标识；不将监测SDR节点默认当作业务接收端。 |
| link_state | enum或null | up、down、degraded、unknown，来自相应端点状态或有说明的估计。 |
| packet_loss_rate | number或null | 范围[0,1]；提供统计窗口、分母与计算方法。I/Q采集丢样不等于业务丢包。 |

### 3.4 网络IDS接口（ids）

原始证据要求：EVE JSON事件，或支持对应协议的PCAP/PCAPNG报文。正常流量可交付flow／stats事件，不强制产生告警。电力协议解析能力由提供方声明。[依据R11/R13](架构图依据说明.md#3-支撑材料)

| 位置／字段 | 类型 | 交付条件 |
| --- | --- | --- |
| metadata.start_time、end_time、interface_id、asset_mapping_version | string，映射版本可null | 证据窗口、采集口和资产映射版本。 |
| data.event_type | string，必填 | 如alert、flow、stats、packet。 |
| data.protocol、src_asset_id、dst_asset_id | string或null | 可识别协议及已映射资产。 |
| data.src_ip、dst_ip、src_mac、dst_mac | string或null | 仅提供报文中实际存在的地址。 |
| data.src_port、dst_port、ether_type、appid | integer或null | 范围[0,65535]；二层GOOSE/SV不强制提供IP／端口。 |
| data.alert_type、severity | string、integer | alert事件必填；其他事件可省略。severity保留原始非负等级，提供方说明尺度。 |
| data.connection_state、flow_id、packet_count、byte_count | string、string或integer、integer、integer，均可空 | 按流记录提供状态、关联标识与计数。 |
| data.protocol_fields、packet_data_uri | object、string，均可选 | 电力协议解析结果及辅助报文位置；字段由双方按协议确认。 |

适配时将EVE的dest_ip/dest_port映射为dst_ip/dst_port，alert.category和alert.severity映射为告警类别和等级。计数保留方向含义或明确汇总规则，不能把单条告警当成全部通信记录。

### 3.5 业务量测接口（business）

原始证据要求：CSV量测／状态序列。每条事件对应一个设备、一个测点和一个时间窗；CSV至少包含timestamp、value列，可增加quality。设备、测点、单位与事件一致，data.value为窗口内最新可用值。[依据R2–R5/R12](架构图依据说明.md#3-支撑材料)

| 位置／字段 | 类型／单位 | 交付条件 |
| --- | --- | --- |
| metadata.start_time、end_time、sample_period_ms | string、string、number ms或null | 窗口与实际采集周期；事件驱动采集的周期可空并说明。 |
| data.asset_id、metric_name、value、unit | string、string、number/string/boolean/null、string | 必须出现；如油温、分接档位、开关位置。不可用值为空，不使用隐藏的真实物理状态补齐。 |
| data.device_quality、device_timestamp | string或null | 原设备质量和原设备时间；未提供则省略或为空。 |
| data.normal_min、normal_max、deviation | number或null | 有基线时提供，说明基线版本及偏差算法。 |
| data.operating_state、control_state | string或null | 工况和控制状态；枚举含义由提供方说明，注明直接读取或推断。 |

单位按测点字典约定，如A、V、W、var、degC、Pa、rpm；档位／枚举／布尔量使用unit=1并提供含义，不能混用一次值与二次值。

## 4. 条件字段与缺失规则

- 整次缺失：data_quality=missing，填写missing_reason，三个raw字段为空，metadata和data为空对象；仍保留事件、提供方及节点信息。未知观测时间可空。
- 可选字段可省略；显式为空的领域字段或采集参数，在field_status中说明原因，如not_decoded、not_calibrated、not_mapped、not_supported、event_driven。原始数据读取／解释所必需的采样率、样本格式等缺失时，不将记录当作有效波形交付。
- 估计结果通过data.feature_info记录method（string）、window_ms（number，正值）及可用的baseline_version（string）；采集配置、原始值与算法估计不得混淆。
- doa_deg为相对已说明参考方向的角度，范围[-180,180]；location为{x_m, y_m, z_m, coordinate_system}，前三项为米制number，最后为string。需有定位证据，不等于节点安装位置或攻击源真值。
- 时间、设备与场景关联由提供方和本方共同确认；各域可以正常或缺失。固定样例回放只能验证接入，若需验证防御反馈，提供方还需支持对应场景参数／状态更新或交付匹配的前后观测。

## 5. 提供方需确认的内容

| 交付项 | 最低要求 |
| --- | --- |
| 能力与责任清单 | provider_id、source_id、负责人；逐字段标记可提供／有条件提供／不能提供，并说明条件。 |
| 数据说明 | 类型、单位、枚举、采样周期、上报周期、触发前后窗口、频段／通带、通道排列、时间精度及校准情况。 |
| 原始证据和事件样例 | 正常、异常、缺失三种情况；证据地址可读取，元数据与文件内容对应。异常标签另交独立评估，不写入识别输入。 |
| 场景关联方式 | 试验标识、设备／测点映射、观测时间依据；回放或生成数据说明模型／数据版本和对底座变化的响应方式。 |
| 交付与变更方式 | 先支持文件包＋JSON Lines，在线传输方式后续协商；字段改变时更新版本，不静默改变含义。 |

JSON Schema校验字段结构、类型、枚举及部分条件约束；接入验收还需核对文件可读性、时间先后、文件头／样本数量、单位、校准与字段来源。格式校验通过不等于真实数据已可获得，也不等于识别或防护效果已验证。
