# 站控网与过程网接入线协议

本文按当前正常运营场景 `scenarios/substation-live.json` 的 `layout.deployment` 整理：每条接入线承载哪些逻辑链路，以及这些逻辑链路使用的协议。

正常场景共 **25 台设备、34 条链路**，其中：

- 站控网：4 条物理接入线、3 条逻辑链路，全部为 **MMS**；
- 过程网：9 条物理接入线、11 条逻辑链路，其中 **6 条 SV、5 条 GOOSE**；
- 其余链路为本地采集、专用对时、控制硬接线、电气/物理耦合或无线链路，不是站控网/过程网以太网协议。

协议标记写在链路参数 `links[].parameters.protocol` 中，前端据此绘制协议线束；`link_type` 仍表示物理连接类型（`wired`、`hardwire`、`physical` 等）。同一套协议标记和差动保护位置已同步到 `substation-em-attack`、`substation-goose-lab`、`substation-sensor-attack`、`substation-time-attack`。

## 1. 站控网接入线

| 接入设备 | 接口/端口 | 承载业务端口 | 逻辑链路 | 协议 |
| --- | --- | --- | --- | --- |
| 站端监控系统 `station` | ETH-ST / P1 | `mc_breaker`, `prot`, `diff_prot` | `L-station-mc`、`L-prot-station`、`L-diff_prot-station` | **MMS ×3** |
| 过流保护装置 `prot` | ETH-ST / P2 | `up` | `L-prot-station` | **MMS** |
| 测控装置 `mc` | ETH-ST / P3 | `up` | `L-station-mc` | **MMS** |
| 差动保护装置 `diff_prot` | ETH-ST / P4 | `up` | `L-diff_prot-station` | **MMS** |

站端监控 P1 一条物理接入线上同时承载 3 条 MMS 逻辑链路。

### 站控网逻辑链路

| 链路 | 两端 | 协议 |
| --- | --- | --- |
| `L-station-mc` | 站端监控 ↔ 测控装置 | **MMS** |
| `L-prot-station` | 过流保护装置 ↔ 站端监控 | **MMS** |
| `L-diff_prot-station` | 差动保护装置 ↔ 站端监控 | **MMS** |

## 2. 过程网逻辑链路

### 2.1 SV：合并单元上报采样值（6 条）

| 链路 | 方向 | 协议 |
| --- | --- | --- |
| `L-mu-mc` | `mu` → `mc` | **SV** |
| `L-mu_2-mc` | `mu_2` → `mc` | **SV** |
| `L-mu-prot` | `mu` → `prot` | **SV** |
| `L-mu_2-prot` | `mu_2` → `prot` | **SV** |
| `L-mu-diff_prot` | `mu` → `diff_prot` | **SV** |
| `L-mu_2-diff_prot` | `mu_2` → `diff_prot` | **SV** |

### 2.2 GOOSE：控制/跳闸命令（5 条）

| 链路 | 方向 | 命令性质 | 协议 |
| --- | --- | --- | --- |
| `L-mc-brk` | `mc` → `ctl_brk` | 断路器分合闸 | **GOOSE** |
| `L-prot-brk` | `prot` → `ctl_brk` | 过流保护跳闸 | **GOOSE** |
| `L-diff_prot-brk` | `diff_prot` → `ctl_brk` | 差动保护跳闸 | **GOOSE** |
| `L-mc-tap` | `mc` → `ctl_tap` | 调压控制 | **GOOSE（简化归并）** |
| `L-mc-cool` | `mc` → `ctl_cool` | 冷却控制 | **GOOSE（简化归并）** |

## 3. 过程网物理接入线

| 接入设备 | 接口/端口 | 承载逻辑链路 | 协议组合 |
| --- | --- | --- | --- |
| 差动保护 `diff_prot` | ETH-PR / P1 | `L-mu-diff_prot`、`L-mu_2-diff_prot`、`L-diff_prot-brk` | **SV + GOOSE** |
| 测控装置 `mc` | ETH-PR / P2 | `L-mu-mc`、`L-mu_2-mc`、`L-mc-brk`、`L-mc-tap`、`L-mc-cool` | **SV + GOOSE** |
| 过流保护 `prot` | ETH-PR / P3 | `L-mu-prot`、`L-mu_2-prot`、`L-prot-brk` | **SV + GOOSE** |
| 断路器智能终端 `ctl_brk` | ETH-PR / P4 | `L-mc-brk`、`L-prot-brk`、`L-diff_prot-brk` | **GOOSE ×3** |
| 分接机构控制接口 `ctl_tap` | ETH-PR / P5 | `L-mc-tap` | **GOOSE** |
| 合并单元 `mu` | ETH-PR / P6 | `L-mu-mc`、`L-mu-prot`、`L-mu-diff_prot` | **SV ×3** |
| 合并单元 `mu_2` | ETH-PR / P7 | `L-mu_2-mc`、`L-mu_2-prot`、`L-mu_2-diff_prot` | **SV ×3** |
| 冷却系统控制接口 `ctl_cool` | ETH-PR / P8 | `L-mc-cool` | **GOOSE** |
| 风机状态监测采集装置 `fan_condition_monitor` | ETH-PR / P9 | 无 `link_ids`，`out` 未接业务链路 | **无业务协议 / 仅本地监测** |

`diff_prot` P1、`mc` P2、`prot` P3 为 **SV + GOOSE 混合接入线**，图上以两支并行线束表示，不能把整条物理线标成单一协议。

## 4. 不经过交换机的本地连接

| 连接 | 类别 | 协议/性质 |
| --- | --- | --- |
| `L-ct-mu`、`L-ct_current_2-mu_2`、`L-vt-mu` | 本地采集 | CT/VT 二次模拟量或低功率互感器信号；**非网络协议** |
| `L-oil-mu` | 本地采集 | Pt100 / 4–20 mA；**非网络协议** |
| `L-fan-vibration-monitor`、`L-fan-current-monitor`、`L-fan-speed-monitor` | 本地采集 | 风机传感器 → 采集装置；`link_type=wired` 但不经过交换机 |
| `L-time-mu`、`L-time_svc_2-mu_2` | 专用对时 | PTP / IRIG-B / NTP 候选；项目未固化协议栈 |
| `L-ctl-brk-down`、`L-ctl-tap-down`、`L-ctl-cool-down` | 控制硬接线 | 电气接点；**非通信协议** |
| `L-brk-tap` | 一次电气 | 电气主接线；无数据协议 |
| `L-tap-oil`、`L-cool-fan-vibration/current/speed` | 物理耦合 | 热传导、振动/电流/转速测点 |
| `L-gnss-time_svc`、`L-gnss-time_svc_2` | 无线 | GNSS 卫星对时；非以太网协议 |
| `L-peer-station` | 无线 | 其他电站 ↔ 站端监控；具体协议未建模 |

正常运营场景没有攻击链路；`L-em-ct` 等干扰链路只出现在攻击场景中。

## 5. 图示约定

图例按组精简为：

```text
MMS   SV   GOOSE   PTP   |   IDS 监测   |   本地连接   电气/物理连接   无线链路
```

| 图例 | 覆盖链路 |
| --- | --- |
| **MMS** | 3 条站控网逻辑链路 |
| **SV** | 6 条合并单元 → 测控/保护/差动的采样值链路 |
| **GOOSE** | 5 条控制/跳闸命令链路（含调压、冷却的简化归并） |
| **PTP** | `L-time-mu`、`L-time_svc_2-mu_2` 两条专用对时链路 |
| **IDS 监测** | 交换机镜像线、IDS 管理上报线，以及检测节点上报线 |
| **本地连接** | CT/VT/油温/风机传感器到采集装置的本地采集接线 |
| **电气/物理连接** | 控制硬接线、一次电气主回路、热传导及风机物理测点 |
| **无线链路** | GNSS 星地链路与其他电站无线链路 |

- PTP 目前只作为图例分组，使用 `timing` 链路样式；场景尚未写入 `parameters.protocol: "ptp"`。
- 混合接入线仍以两条并行协议线束表示（SV 与 GOOSE 各一支）。
- 前端在 `network-topology.js` 中按 `network.link_ids` 汇总每条接入线的协议集合；`app.js` 按协议类名绘制并行路径，图例按上述分组展示。

## 6. 关于调压/冷却的简化口径

本项目图示按“控制命令 = GOOSE”统一处理，因此 `L-mc-tap`、`L-mc-cool` 标为 GOOSE。这是**本项目展示口径**，不代表现场一定使用 GOOSE：

- 调压（有载分接，参考 R15/TAPCON 230）可能使用 IEC 61850、Modbus、IEC 60870-5-101/104、DNP3、串口或硬接点；
- 冷却（参考 R16/CoreSense+、ETOS TD）现场常以继电器/接触器硬接点分级启停，数字化后可能是 Modbus 或 IEC 61850。

底座内部这两条链路仍只承载 `command`/`feedback` 业务消息，不实现真实协议栈；后续如接入真实协议，应把 `parameters.protocol` 改为对应值并补充依据。
