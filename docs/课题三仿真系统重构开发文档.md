# 课题三仿真系统开发目标与架构

具体文件树、类、函数与调用关系见[详细开发设计](课题三仿真系统详细开发设计.md)。

## 1. 开发目标

利用AI核查并重构变电站设备及其交互关系，建立能够运行正常业务、表达攻击影响，并接入协同课题组提供的五类观测数据以支持课题三识别与防御的轻量仿真底座。

以仿真底座为核心，按攻击、识别和防御平面组织扩展能力，通过演示平面提供统一UI，后续可分别增加设备、场景和攻防方法。

课题指标：电磁监测覆盖15 kHz—24 GHz，声波监测覆盖20 kHz—200 kHz，攻击识别准确率均不低于95%，设备针对有效攻击的防护成功率不低于90%。

## 2. 架构组成

系统按五个平面组织开发。平面划分描述软件职责；过程层、间隔层、站控层是仿真底座内部的设备组织，两者不是同一层级。

| 平面 | 职责 | 对外提供 |
| --- | --- | --- |
| 仿真底座平面 | 运行设备、连接、环境和正常业务；计算攻击与防御作用后的状态及影响传导 | 外部观测的统一接入、可控能力及执行反馈 |
| 攻击平面 | 组织电磁、声波、无线、网络及协同攻击，向选定对象施加作用 | 攻击作用请求：目标、作用类型、参数、起止时间及顺序 |
| 识别平面 | 根据可观测证据进行异常判断、攻击识别和跨域关联 | 识别结果：疑似类型、关联设备、证据与置信度 |
| 防御平面 | 结合识别结果、当前观测和设备能力选择处置，并检查恢复情况 | 防御请求：目标、动作、参数及有效时段 |
| 演示平面 | 提供统一UI，展示系统运行与攻防过程，支持场景选择、运行控制和回放 | 展示视图及用户操作请求 |

五类监测接口及数据由对应协同课题组提供，本方负责声明数据需求、接入校验和关联适配。底座中的监测接入部分是识别与防御的数据入口，监测算法、I/Q／PCM采集或生成不由本方在此设计。攻击、防御均通过约定接口作用于底座，由底座统一更新状态；是否异常、是否致效由实际作用条件决定。五个平面可先实现为同一程序中的独立模块。

本文重点展开仿真底座及跨平面接口；三层设备与运行环境均属于底座。独立评估使用攻击真值评价识别和防护效果，真值不进入识别与防御输入。

### 2.1 底座实体

| 所属部分 | 实体 | 职责 |
| --- | --- | --- |
| 过程层 | 一次设备及辅助系统 | 被监测的物理对象及其可控部件，如开关、变压器与分接机构、补偿设备、冷却系统；承担电气、机械或热过程。 |
| 过程层 | 感知设备 | 感知电流、电压及温度、压力、振动等状态；互感器和各类传感器是具体实例。 |
| 过程层 | 采集与处理设备 | 将感知信号转换为可用数据；包含合并单元、状态采集模块和专用分析装置等。 |
| 过程层 | 控制接口设备 | 将控制请求转换为动作或设定值并采集反馈；包含智能终端、驱动控制器和执行接口模块等。 |
| 间隔层 | 状态监测装置 | 汇集设备状态与诊断结果，向站端上报异常和告警。 |
| 间隔层 | 保护装置 | 根据电气采样值判断故障，发出跳闸指令并上报保护事件。 |
| 间隔层 | 测控装置 | 形成业务量测，检查并下发操作命令，跟踪执行状态。 |
| 站控层 | 站端监控系统 | 汇集量测、状态和事件，支持操作、监视、记录及对外通信。 |
| 站控层 | 授时系统 | 接收GNSS等时间源，为需要对时的设备提供时间基准。 |
| 跨层通信 | 无线传输终端 | 将采集单元的状态数据送入无线链路，按场景选配。 |
| 跨层通信 | 无线接入网关 | 接收无线数据，经站内网络转发至状态监测装置，按场景选配。 |
| 跨层通信 | 站内通信网络 | 承载设备之间的数字报文，表达链路连通、时延和丢包等状态。 |

过程层的四类是依据工程功能作出的仿真归纳，不是标准规定的四种设备。类别可以集成在同一实物中，例如传感器自带采集、控制器兼有就地调节；其三层归属表示功能组织，不限定安装位置。[分类依据](架构图依据说明.md#11-过程层分类依据)

“一次设备及辅助系统”中的典型受控对象如下，断路器只是开关类的一个实例：

| 对象类别 | 典型实例与可控动作 | 需要表达的状态及影响 |
| --- | --- | --- |
| 开关类 | 断路器、隔离开关、接地开关；按能力分合与联锁 | 位置、动作时间、接线通断及供电状态；可按监测配置增加机构振动、线圈电流。 |
| 变换与调压类 | 变压器及有载分接机构；调整分接档位 | 档位、变比及电压变化；负载和损耗引起的温度变化按简化模型传导。 |
| 无功补偿类 | 可投切电容器组、电抗器支路；投切或按能力调节 | 投入状态、无功功率及其对电压的影响。 |
| 辅助运行类 | 变压器冷却风机、油泵等；启停、分组或按能力调速 | 运行状态、冷却能力及油温／绕组温度变化；转速、振动等仅在可采集时输出。 |

断路器动作不仅改变电气通断，也伴随机构运动、位置和振动变化；对其他设备温度的影响通常通过负载、损耗等间接传导，不能直接令所有状态量同时变化。[对象与影响依据](架构图依据说明.md#11-过程层分类依据)

母线、电缆等可作为电气连接与参数建模，不必都封装成可控设备。每个可控实例只声明实际支持的动作、状态和反馈；隔离开关、接地开关不能直接复用断路器的故障开断逻辑。

### 2.2 实体间的接口

图中绿色箭头是物理状态对感知设备的作用，其余箭头表示数据或控制方向。接口按实例能力配置：合并单元支路可采用SV，开关控制支路可采用GOOSE或硬接线，调压与冷却支路使用匹配的驱动／控制接口。仿真仍用简单消息保留这些语义。

| 连接关系 | 功能 | 最小数据内容 |
| --- | --- | --- |
| 一次设备及辅助系统 → 感知设备 | 感知物理过程 | 接入测点的电流、电压、温度、压力或振动等物理作用；只向监测提供经传感与采集后的读数。 |
| 感知设备 → 采集与处理设备 | 信号采集与转换 | 通道、读数／波形、单位及转换配置；时间由采集端记录。 |
| 采集与处理设备 → 状态监测装置 | 状态汇集与分析 | 测点、状态值、单位、采集时间及可用的质量、诊断结果。 |
| 采集与处理设备 → 保护装置、测控装置 | 电气采样与量测 | 通道样值与质量；SV实例另保留采样流标识、采样计数和同步状态。 |
| 保护装置 → 控制接口设备 | 保护动作，按可保护支路配置 | 目标、动作请求和时间；GOOSE实例保留状态号与报文序号。 |
| 测控装置 ↔ 控制接口设备 | 操作／设定与反馈 | 目标、动作／设定值、单位；返回受理情况及位置、档位、启停等可读状态。 |
| 控制接口设备 ↔ 一次设备及辅助系统 | 物理执行与状态返回 | 按实例传送分合、升降档、投切、启停或调速请求，并返回实际可获得的反馈；请求值不等于实际状态。 |
| 状态监测装置、保护装置、测控装置 → 站端监控系统 | 监视与记录 | 测点／事件标识、值／状态、时间及可用的质量。 |
| 站端监控系统 → 测控装置 | 下发操作 | 目标、操作类型、请求值及关联标识。 |
| 授时系统 → 需对时的设备 | 提供时间基准 | 时间信号／报文；时间源与同步状态按管理接口能力提供。 |
| 采集与处理设备 → 无线传输终端 → 无线接入网关 → 站内通信网络 → 状态监测装置 | 可选无线状态通路 | 保留原状态数据；接收时间和链路统计按实际接口补充。 |

类别之间的连线表示可配置的逻辑关系，不要求所有实例走同一条链。就地调压或冷却控制可集成在控制接口设备中，站端／间隔层主要下发设定与接收状态；不强制每次动作都由站端发起。字段及工程接口依据见[接口依据](架构图依据说明.md#1-接口依据)。

业务闭环为“物理对象—感知—采集—判断—控制—物理对象”。初期用少量状态及简化方程表达电气、机械和热影响，保留各自响应时序，无需建模完整机械结构、流体过程或攻击实现机理。

### 2.3 演示平面

演示平面面向系统使用者，提供三个主要视图：

- **系统运行**：设备拓扑、连接状态、业务量测及五类观测摘要，支持查看原始证据及数据缺失情况。
- **攻防过程**：在同一时间轴上展示攻击配置与执行记录、识别结果、防御动作和设备响应，并区分计划、判断与实际执行。
- **效果对比**：展示正常、攻击无防御、攻击有防御场景的业务变化及独立评估结果。

UI支持选择场景、启动／暂停运行、选择攻防配置和回放记录。操作通过接口交给对应平面执行，UI依据返回状态更新；展示层不承担仿真计算或识别、防御决策。初期采用简单页面与图表，复用已有数据。

仿真内部状态、外部观测和算法结果分别标明来源；回放标明记录时间。攻击真值仅在评估视图中标识展示，不经UI回流到识别与防御输入。

## 3. 接口数据约定

### 3.1 对协同课题组的数据需求

五类接口采用统一JSON事件头，分别附采集元数据、领域数据及原始证据地址。以下是本方提出的交付需求，具体提供方和支持字段待协同确认。

| 接口 | 需提供的主要内容 |
| --- | --- |
| 电磁 | I/Q或注明采集方式的实数波形、采样率、格式、频段、增益及校准状态；可用的信号特征。 |
| 声波 | PCM文件、采样率、位深、通道及校准信息；可用的声学特征。 |
| 无线SDR | 原始I/Q及采集元数据；可解码身份、关联接收端和可获得的链路统计。 |
| 网络IDS | EVE事件或报文证据、采集口、可见地址和协议；告警或流统计按实际能力提供。 |
| 业务量测 | 设备、测点、值／状态、单位、时间及可用的质量标记，并附时序文件。 |

完整字段名、类型、单位、必填条件、缺失规则及交付清单统一见[五类监测接口数据交付规范](五类监测接口数据交付规范.md)，附JSON Schema和结构示例。原厂资料只说明可能的数据获取途径，不代表协同方已经承诺提供。

### 3.2 本方接入职责

本方校验事件和证据格式，维护提供方／节点与底座设备的映射，按时间和场景关联观测，并供识别、防御读取。无法获得的数据保持缺失，不自行生成替代证据冒充协同方交付；底座内部业务状态与外部观测分别记录。

协同方需说明数据是实测、回放还是生成。用于闭环验证时，还需约定观测如何随攻击、防御及底座状态变化；固定文件回放只验证接入，不单独证明闭环效果。

### 3.3 跨平面接口

| 交互 | 提供数据 | 来源与限制 |
| --- | --- | --- |
| 攻击 → 底座 | 作用标识、目标实体／链路／通道、作用类型、参数、起止时间及步序 | 可用信号回放或简化异常作用表达读数偏移、时序扰动、丢包等；底座检查作用条件并计算结果，不直接预设攻击成功。 |
| 协同方 → 底座接入 → 识别、防御 | 五类观测事件及原始证据索引 | 只提供可观测数据，保留缺失与质量信息；不附攻击配置中的真实目标或标签。 |
| 识别 → 防御 | 识别标识、疑似攻击类型、关联设备、证据引用和置信度 | 算法输出，允许未知或证据不足。 |
| 底座 → 防御 | 可控目标、支持的动作、参数范围及可见运行状态 | 来自能力配置或可读管理接口，不默认设备支持调频、滤波或阻断。 |
| 防御 → 底座 | 动作标识、目标、动作、参数、有效时段及关联识别结果 | 由底座校验并执行，保留与正常控制之间的联锁和优先关系。 |
| 底座 → 防御 | 动作标识、受理／执行状态、失败原因及后续观测引用 | 受理、执行完成与防护有效分别确认，恢复后的变化继续进入五类接口。 |
| 各平面、独立评估 → 演示 | 拓扑与状态、观测摘要／证据引用、攻击记录、识别结果、防御反馈及评估结果 | 复用原有输出，按场景、时间和设备关联；明确数据来源、缺失及实时／回放状态，评估真值单独展示。 |
| 演示 → 对应平面／实验控制接口 | 请求标识、场景、操作类型及参数；返回受理／执行状态和失败原因 | 场景选择、启停、攻防配置和回放操作由对应模块处理；UI不能直接改写设备状态或算法结果。 |

这些衔接字段属于项目内部约定，与[攻击者](系统角色设计.md#33-攻击者)和[防御者](系统角色设计.md#35-防御者)的职责对应。工程资料用于证明数据或执行接口可获得，防御效果通过后续观测与独立评估确认。

## 4. 运行与建模原则

底座运行正常业务 → 攻击平面提交作用 → 底座计算状态并接入协同方观测 → 识别平面判断 → 防御平面提交处置 → 底座执行并接入后续观测。未启用攻击时，底座也能独立运行正常业务。

- **轻量建模**：用规则与简化方程描述影响及传导，通信采用简单消息，保留必要时序。
- **数据一致**：各域数据由同一场景驱动，原始证据、特征和业务响应相互对应；不强制每次攻击产生五域异常。
- **证据保留**：保存协同方提供的原始证据及来源说明；回放／生成数据须明确标记，不用预设指纹编号替代I/Q。
- **能力可扩展**：五个平面通过稳定接口连接，设备模型、攻击方法、识别算法、防御策略和展示视图可分别增加或替换。
- **真值隔离**：真实攻击标签供独立评估使用，不直接提供给识别与防御。

## 5. 验证目标

验证正常业务闭环、五类接口接入、跨域影响关联和防御反馈。重点检查声波或电磁异常与设备量测的关联、无线异常与链路变化的关联，以及网络行为与业务后果的关联；按选定对象验证开关位置、调压档位或冷却温度等响应。

同时支持正常对照、攻击无防御、攻击有防御三类场景，以及部分接口无异常或数据缺失的情况。

演示验证重点是页面与实际输出一致、操作状态可追踪、同一场景下的时间轴与回放对应，并清楚区分观测、算法判断和评估真值。
