# 声波干扰联动演示

这次把三个任务接进了现有网页：可以看虚拟声波、XYZ 读数、电流/转速/油温曲线，以及本次运行实际产生的控制路径日志。**全部运行在本地，没有连接真实设备。**

当前版本同步至 `main` 的 `63c9472`（2026-10-19 12:16）。拓扑以该版本的 `scenarios/substation-sensor-attack.json` 为模板，保留 27 个设备、原有 35 条连接及 MMS/SV/GOOSE 协议分组，额外增加 1 条风机状态上送链路。模板版本及统一为 LF 换行后的 SHA256 保存在 `scenario.json` 的 `layout.acoustic_template` 中。

## 怎么打开、怎么演示

在仓库根目录运行：

```powershell
python run_acoustic.py --port 8768
```

浏览器打开 <http://127.0.0.1:8768>，点击顶部“声波联动”，再点击“载入声波场景”。也可以从左侧选择“声波干扰联动（仿真）”，然后创建运行。

这个专用入口的左侧只显示声波场景。电磁攻击、网络攻击等是公共代码库原有的其他研究场景，无需加入声波汇报；它们的文件和公共服务 `run_server.py` 保持原样。

推荐顺序：

1. 点击“推进 10 秒”：看正常读数，风机仍通电。
2. 点击“原样本幅度 κ=0.30”，再推进 10 秒：XYZ 有扰动，但没有达到停机条件。这里复用旧 S 样本的幅度设定；连续开启时长由按钮控制，并非逐行播放旧 CSV。
3. 点击“新建正常对照”：开始独立的新运行，旧运行的记录会保留。
4. 推进 10 秒，开启“增强仿真 κ=0.90”，再推进 10 秒：看到连续超限、停机路径和回执。该增强档是新增的假设场景。
5. 关闭干扰，再推进 10～20 秒：看停机全过程。电流快降、叶片逐渐停下；加速演示油温出现明显升高，同时灰色虚线保留原时间尺度的缓慢变化。关闭声波不会自动重启风机。
6. 需要恢复时，关闭干扰，推进至少 2～3 秒，点击“复位保护”，再点击“启动风机”。

XYZ 可以分别查看。关闭干扰后，前两张图默认保留最近一次通电受扰片段，避免演示结果被空白曲线替换；标题明确显示其历史时刻。“显示当前片段”可以切回当前读数。其余曲线始终显示本次运行的时间过程。

油温状态卡读取 `oil_temp` 节点最近实际产生的仿真采样，并显示其采样时刻；不会用两个采样时刻之间尚未上报的内部连续模型值冒充节点读数。灰色原尺度对照按同一采样时刻配对。网络转报还会晚几个仿真步，日志中的接收时间因此可能与采样时刻不同。

**油温默认采用加速演示：只将热惯性压缩 360 倍，自然散热时间常数由 7200 秒改为 20 秒。声波、风机电流、转速、通信和 1 秒判据窗口的时间不加速。快慢两条油温都属于未实测标定的模型，不能把演示中的升温速度说成真实设备速度。**

## 数据和模型从哪里来

| 内容 | 来源 / 用途 | 不能据此声称什么 |
|---|---|---|
| 正常 XYZ | TI 风机数据集 Normal，ADXL355 原始计数，首个文件前 4 秒、16000 行，4000 Hz；循环回放 | 不是本项目变电站风机的现场数据；重复回放不是新采样 |
| 参考响应 | ADI 的 ADXL356 X 轴示例模型，f₀=5500 Hz，Q=17，低通 1500 Hz | 不是 ADXL355 或目标设备的已标定声学响应 |
| XYZ 耦合 | 共用响应，权重 1、0.6、0.3，并乘各轴正常标准差 | 权重、相位和共用频响均未由三轴实测确定 |
| 两个幅度档 | κ=0.30 沿用旧 S 样本幅度，κ=0.90 为新增增强假设 | κ 不是 Pa、dB 或扬声器功率；不能换算真实攻击距离 |
| 停机规则 | 站控设备 `station` 判断收到的窗口：任一轴去均值 RMS（去掉固定偏置后衡量波动大小）超过正常基准 2 倍，连续 3 个完整的 1 秒窗口；设备等待 1 秒再下发 | 这是研究演示规则，不是现场控制器已确认的保护逻辑 |
| 电流、转速、油温 | 当前 2 A、1500 rpm；电流时间常数 0.25 s、转速 5 s；油温并列保存自然散热时间常数 20 s 的加速演示与 7200 s 的原尺度对照 | 两种油温都不是实测；加速曲线不能用于预测真实升温速度或现场整定 |
| 路径日志 | 本次底座消息真实投递到仿真节点时记录，命令和回执共用 request_id | 是应用层仿真，不是交换机日志、真实 IDS 事件或 PCAP 抓包 |

来源：[TI 正常风机数据](https://github.com/TexasInstruments/tinyml-tensorlab/blob/main/tinyml-modelzoo/examples/fan_blade_fault_classification/readme_anomaly_detection.md)、[ADI 参考响应模型](https://www.analog.com/en/resources/analog-dialogue/articles/mems-vibration-monitoring-acceleration-to-velocity.html)。热过程沿用此前确认的能量平衡思路，可参考 [Roslan 等，Energies 2017，10(11):1843](https://www.mdpi.com/1996-1073/10/11/1843)；本文采用的风冷系数与转速比例关系及全部具体参数仍是自己的演示假设。

原文件名称、原文件/压缩包/本地片段的 SHA256（用于核对文件内容有没有变）保存在 `data/provenance.json`。数据只保留三列 `baseline_x_count`、`baseline_y_count`、`baseline_z_count`；第 n 行的时间为 n/4000 秒。原始 Z 轴编码偏置被保留，计算波动幅度时会去均值。

## 一条完整的产生路线

```text
真实正常 XYZ 片段（循环回放） ────────────────────────┐
                                                    ↓
虚拟声波 u(t) → 连续参考响应 H(s) → 三轴扰动 ΔXYZ → 受扰 XYZ
                                                    ↓
                1 秒完整窗口 → 采集装置 → 测控 → 站控连续超限判据
                                                    ↓
                等待 1 秒 → 站控发命令 → 测控 → 冷却控制 → 风机
                                                    ↓
                真正执行断电 → 电流快降 / 转速慢降 → 风冷减弱 → 油温慢升
                                                    ↓
                执行回执：风机 → 冷却控制 → 测控 → 站控
```

没有直接从“声波已开启”跳到“停机”。判据只使用站控实际收到的窗口读数，读取不到数据就不能触发。控制链路中断，即使站控已经决定停机，风机也不会凭空断电。本轮新实现补上了以前“声波样本”和“预设停机对照”之间没有接通的部分。

判据、连续超限次数、锁定状态、等待时间和停机请求编号均归属于 `AcousticStation`（站控设备），可从 `station` 的设备快照查看。站控先接收测控转报，再在自己的 `step()` 中评估；到期后仍由该设备的 `step()` 形成并返回停机命令，经底座网络送出。`AcousticApplication` 只做装配、声波手动操作和记录，已经移除原来由应用层调用 `engine.submit_business_operation()` 代发保护停机的做法。

风机采集装置用独立的 MMS 状态链路 `L-fan-monitor-mc` 上送风机状态。测控装置把它作为状态监测信息转报给站控，不混入业务量测 `sources`；两套 SV 业务量测来源仍是 `mu`、`mu_2`，差动保护、第二套传感器/授时链和原有协议分组全部保留。

油温测量路径为“油温传感器 → 合并单元 → 测控 → 站控”；不经过风机控制接口。风机电流、转速、振动走“风机采集装置 → 测控 → 站控”。

## 数学上检查的是什么

虚拟等效输入是 `u(t)=κ·e(t)·cos(2π·5500·t+φ)`，e(t) 在开关边缘采用 20 ms 升余弦包络（用短暂平滑过渡避免突然开关）。参考传递关系为：

```text
H(s) = ω₀² / (s² + (ω₀/Q)s + ω₀²) × ωc/(s+ωc)
Δaᵢ[n] = σᵢ · wᵢ · r(n/4000)
观测值 yᵢ[n] = 机械基线 bᵢ[n] + Δaᵢ[n]
```

σᵢ 是正常 4 秒片段中对应轴的标准差；wᵢ 分别是 1、0.6、0.3。风机降速时，机械基线相对均值的波动幅度按转速比例衰减，这是新增的简化假设，不是实际停机振动记录。

本地实现用解析解（把连续微分方程直接算出响应）替代旧版离线数值积分，不是逐行回放旧攻击 CSV。它先计算连续域的高频作用，再按 4000 Hz 读取输出，避免先把 5500 Hz 输入降采样后误当成低频激励。输入图以 88000 Hz 显示数学函数，传感器图则显示 4000 Hz 的读数；采样后的 1500 Hz 表观分量属于混叠（高频信号被较慢采样“看成”另一个频率），不代表真实输入变成了 1500 Hz。本模型没有完整复现 ADXL355 内部模拟/数字采样链路。

测试包括：稳态响应对照频域公式；开关暂态对照独立的 256 kHz RK4 数值积分；三轴加法、幅度比例、源文件校验，以及旧 TI01_S 第 1～2 秒窗口统计的近似复现。新解析解与旧数值积分有小差异，测试明确限定误差，而非宣称 CSV 完全相同。

电流和转速采用一阶变化（朝目标逐渐接近）：断电后 I=I₀exp(−Δt/0.25)，n=n₀exp(−Δt/5)。**I 表示具有滞后的电流有效值读数，不是说断电后真实导线持续通着该电流。**

油温方程为：

```text
C·dT/dt = P损耗 − (G自然 + G风冷·r)·(T−T环境)
C参考=3600000 J/K，P损耗=30000 W，G自然=G风冷=500 W/K
r=转速/1500，T环境=25 ℃，初始 T=55 ℃
```

为使组会演示能看出变化，保持发热、散热系数和温度平衡点不变，仅把用于演示的有效热容设为 `C有效=C参考/360=10000 J/K`。因此自然散热时间常数 `τ=C/G自然` 从 7200 秒变为 20 秒；风机满速时，总散热系数为 1000 W/K，对应时间常数分别为 3600 秒、10 秒。这个加速参数在 `tap.parameters.acoustic_thermal.time_scale` 中设为 360；设为 1 可恢复原尺度。

灰色对照曲线同时使用原热容 3600000 J/K、相同的发热和风机转速过程独立计算。它不是实测数据，也不是对加速曲线做简单横坐标重标记：只压缩热惯性，风机滑行与电流过程都保持原来的秒数。两条温度传感器读数都保留 5 秒滞后。

例如在模型中从满速断电、计算 12.5 秒后，加速油温读数约为 60.238 ℃，原尺度读数约为 55.018 ℃，初始值同为 55 ℃。该对比只说明演示参数使温度变化可见，不能说明真实设备会在 12.5 秒升温约 5 ℃。

这里 30000 W 是变压器损耗发热，不是风机功率。初始散热恰好抵消发热；停机后自然散热仍存在。温度按 0.1 秒以内步长更新。较短振动采样块内使用块结束时的转速近似机械基线幅度；这也不是精细的机械动力学模型。

这页假设负载和损耗发热保持不变，目前没有把断路器开断、负载变化等其他操作重新接入热模型。请用本页按钮演示声波与风机的关系，不把它理解为完整变电站的联合热仿真。

数学检查说明“按这套假设，计算关系和控制链路自洽”。**仍然不能证明具体传感器可被真实声波攻击，更不能证明已经使现场设备停机。**

## 断电时间和日志怎么看

断电时间由这次运行计算出来，不再固定为旧版 304 秒。例如：先推进到 10 秒开启增强档，首次三个超限窗口结束后，站控收到第三个窗口、等待 1 秒、再逐节点转发并执行，断电约发生于 14.6 秒。它不是预先安排在 14.6 秒；改变开启时刻或通信链路，就会改变结果。

当前底座步长是 0.1 秒。虽然链路配置的延迟可能是 1 ms，消息只能在后续仿真步被设备处理。因此界面中的各跳接收间隔包含调度步长，不能当作真实网络时延。`source_time_s` 是保留的消息/测量源时间，`scheduled_delivery_s` 是网络模型排定的送达时间，`observed_time_s` 是实际被本次仿真步处理的时间。

`accepted` 表示设备受理，`completed` 表示设备完成执行。请根据同一个 `request_id` 连起命令和回执，再对照实际断电时间、电流和转速。声音关闭和保护复位是两件事：保护锁定后，需要正常窗口、人工复位、再发启动命令。

每次运行记录自动保存在仓库的 `runs/<运行编号>/`：

- `acoustic_meta.jsonl`：模板版本、来源、判据、热容和热加速系数。
- `acoustic_series.jsonl`：每秒 XYZ 波动比、电流、转速、加速模型油温、加速油温读数和原尺度油温对照。
- `acoustic_path.jsonl`：设备判据事件、命令/回执实际投递、站控收到的测量。判据/发令事件标有 `owner_device_id=station`，发令事件另标明 `emitted_from=AcousticStation.step`。
- 底座原有 `business.jsonl`、`truth.jsonl` 等继续保存。以上记录都属于本地仿真。

新增声波标签页目前展示服务中的活动运行。服务重启后，旧 JSONL 文件仍在，但本标签页尚未实现从旧运行文件恢复整套交互图表；原底座的快照读取机制保持原样。
